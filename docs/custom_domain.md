## Кто кого блокирует: Google vs Роскомнадзор

При попытке использовать Google Gemini в РФ разработчик сталкивается сразу с двумя независимыми барьерами:

- барьер со стороны Google (геоблок): компания Google со своей стороны блокирует все запросы к API с российских IP-адресов, возвращая ошибку 403 Forbidden
- барьер со стороны ТСПУ / РКН (фильтрация SNI): технический домен Cloudflare `*.workers.dev` глушится на российских сетях через фильтрацию поля SNI при TLS-рукопожатии (соединение сбрасывается ошибкой `ERR_CONNECTION_CLOSED`)

Именно поэтому стандартный воркер по умолчанию требует постоянного включения стороннего VPN.

## Почему не работает технический домен workers.dev

[По данным независимых сетевых отчетов OONI Explorer](https://ooni.org/post/2024-russia-blocked-ooni-explorer/), оборудование ТСПУ перехватывает незашифрованный заголовок Server Name Indication (SNI) в стартовом пакете TLS ClientHello.

Если в заголовке содержится имя `*.workers.dev`, провайдер принудительно шлет пакет `TCP RST` (разрыв соединения). Это вызвано тем, что на бесплатном домене `workers.dev` размещались тысячи немодерируемых публичных зеркал и прокси.

## Почему Custom Domain работает напрямую

Архитектура Anycast Cloudflare позволяет полностью устранить оба барьера:

- IP-адреса Cloudflare не заблокированы в РФ, так как на них работают миллионы легальных ресурсов Рунета
- при добавлении своего домена (например, `gateway.mydomain.ru`) клиент Zed отправляет в поле TLS SNI имя вашего личного домена, которого нет ни в каких списках фильтрации ТСПУ. Соединение из РФ до серверов Cloudflare проходит напрямую и на полной скорости
- сам воркер исполняется в глобальной сети Cloudflare за пределами РФ. Когда воркер отправляет исходящий запрос к Google API (`generativelanguage.googleapis.com`), серверы Google видят европейский или американский IP-адрес датацентра Cloudflare, где нет никаких санкционных ограничений
- ответ от Google транслируется обратно в ваш редактор Zed

Итог: честный сквозной сетевой мост без необходимости держать локальный VPN или прокси на компьютере.

## Делегирование домена на Cloudflare (Beget, Reg.ru, TimeWeb и пр.)

Если у вас уже есть домен, добавленный в Cloudflare, переходите сразу к следующему разделу. Если домен куплен у стороннего регистратора, его нужно один раз привязать к Cloudflare.

Подойдет любой дешевый домен в зоне `.ru`, `.site`, `.dev` или рабочий поддомен.

### Добавление домена в аккаунт Cloudflare

- откройте панель управления [Cloudflare Dashboard](https://dash.cloudflare.com/)
- в верхнем меню выберите **Websites**
- нажмите синюю кнопку **Add a domain**
- введите имя вашего домена (например, `mydomain.ru`)
- выберите бесплатный тарифный план **Free Plan** и нажмите **Continue**
- Cloudflare просканирует текущие DNS-записи и покажет два назначенных NS-сервера (например, `ashley.ns.cloudflare.com` и `bob.ns.cloudflare.com`)

### Смена NS-серверов у регистратора

Откройте личный кабинет регистратора, где зарегистрирован ваш домен:

- **Beget:** перейдите **Домены и поддомены** -> нажмите на шестеренку управления доменом -> выберите **Изменить NS-серверы** -> укажите адреса серверов Cloudflare
- **Reg.ru:** перейдите **Мои домены** -> выберите домен -> раздел **Управление** -> блок **DNS-серверы и управление зоной** -> нажмите **Изменить** -> переключите на «Свой список DNS-серверов» и введите адреса Cloudflare
- **TimeWeb:** перейдите **Домены и поддомены** -> выберите домен -> вкладка **DNS** -> выберите **Свои NS** и сохраните значения Cloudflare

Обновление DNS-серверов в мировых таблицах занимает от 15 минут до пары часов. В панели Cloudflare статус домена сменится на зеленый `Active`.

## Привязка Custom Domain к воркеру в Cloudflare

После активации домена привязка к шлюзу выполняется в пару кликов:

- в левом меню Cloudflare выберите раздел **Workers & Pages**
- в списке проектов нажмите на `gemini-edge-gateway`
- на верхней панели выберите вкладку **Settings**
- в левом меню настроек перейдите в подраздел **Domains & Routes**
- в блоке **Custom Domains** нажмите кнопку **Add** -> **Custom Domain**
- введите имя желаемого поддомена (например, `gateway.mydomain.ru`)
- нажмите кнопку **Add Custom Domain**

Cloudflare автоматически создаст CNAME-запись в DNS-зоне и выпустит бесплатный SSL-сертификат. Через 1--2 минуты статус поддомена станет `Active`.

## Настройка Zed IDE

После активации домена:

- откройте конфигурационный файл Zed `settings.json`
- укажите персональный адрес шлюза:
```json
"api_url": "https://gateway.mydomain.ru/v1"
```
- удалите или закомментируйте параметр `"proxy"`, если он был настроен для обхода
- отключите VPN на устройстве
- сделайте любой запрос ассистенту Zed

Агент будет отвечать напрямую через Anycast-сеть Cloudflare с минимальным сетевым пингом и без задержек туннелирования.
